# Phase 3 development search

This record fixes the comparison before the first development batch. Open development seeds are 1, 2, 3. Each of the nine candidate slots per method receives precisely one score per seed. All runs use experiment 4, 60 vehicles, vehicle 30, the stage 2 evaluator and the same paired exogenous inputs. The equal budget counts candidate evaluations. Deterministic baseline and integrity replays do not count as search trials. No validation or test input is used in this phase.

## Methods and selection

The fixed family holds the original stage 1 trigger (average speed within 800 m below 20 m/s) and one-shot release logic. Its predeclared grid crosses desired speeds 8, 14, 20 m/s with durations 30, 65, 100 s. All caps release by position 4500 m. The family comes from stage 1; Codex selected its grid before the search. It is an engineering control, not evidence about an unaided human designer.

The LLM uses three sequential batches of three decision tables. All three proposals in a batch are saved before evaluation. A new batch may read earlier development feedback. No model weights are trained. The proposal generator is this interactive OpenAI Codex session (GPT-6 family; specific serving snapshot and sampling settings unavailable). Each brief and its machine-readable response are archived. The briefs are experiment instructions prepared within this session. No separate API request or independent human prompt is implied. Snapshots in Git record the order. In keeping with the staged coursework, the next phase can replay the two best eligible rules per method on the reserved validation split before freezing one each. Rank by unrounded mean reward across all three eligible seeds, then ascending rule ID if exactly tied. An ineligible seed excludes a rule from ranking. Include all failures.

## Fixed rule interface

Vehicle 30 updates its requested IDM desired-speed ceiling once per simulated second. IDM acts every 0.1 s and uses the lower of the requested ceiling and the road target at each physics step. All simulated vehicles can still brake or travel below the target while following. Only upstream action is permitted; each rule starts at most once and ends at its time limit, upstream boundary or optional release condition. Crossing the boundary is detected at the next one-second decision. All methods have the same observations and actuator; the fixed family only needs the forward mean. List entries in start and release are AND conditions. An empty release list disables this optional trigger.

The observable fields are current ego position (m) and speed (m/s), active leader speed (m/s) and net gap (m), and mean speed of active vehicles strictly ahead within 800 m (m/s). `zone_speed` averages vehicle-speed samples from the fixed 4300–4500 m approach over the current and four preceding one-second samples. `entry_rate` is vehicle crossings of 4500 m per second over those five bins. At startup only available bins are used. Empty speed/gap observations are null; a missing trigger condition cannot match. A missing target input holds the previous request. Sensor access is idealized. Rules cannot inspect IDs, seeds, future states, scores, other controllers or historical test outcomes.

The target tuple is [feature, gain, offset, floor, ceiling]. While active, clip gain × feature + offset to the two speed bounds. The maximum downward change in requested speed per decision is `drop` in m/s, measured from ego speed at activation and the previous requested ceiling thereafter. Upward changes take effect immediately. Durations are seconds and positions are metres.

## Scoring and feedback

Use the phase 2 percentage-improvement weights for total travel time (0.5), follower speed variation (0.3), low-speed exposure (0.1) and last exit (0.1). The last two times are measured for the same full scheduled cohort indicated in the plan (low-speed exposure counts only time on the road). For each candidate save the raw paired metrics, individual improvements where defined, eligibility, sampled overlap flag and minimum gap. Logged decisions include current road target, requested ceiling, effective target at the observation and the lowest realised ego acceleration during the following decision interval. This last quantity is added offline. For feedback, display the strongest-braking active interval and adjoining decisions plus the release observation. A small sampled gap or sharp brake is a diagnostic signal; only the predeclared phase 2 rejection criteria determine eligibility.

[He and colleagues' JAD implementation](https://github.com/gotrafficgo/jam_absorption_driving) motivates using one vehicle to influence a following platoon. [DeepMind's FunSearch repository](https://github.com/google-deepmind/funsearch) motivates keeping proposals separate from external scoring. The code here implements a manual, budget-limited adaptation in the course simulator.
